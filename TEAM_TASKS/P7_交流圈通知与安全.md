# 任务卡 · P7 交流圈 + 通知 + 账户安全

## 你的角色
实现交流圈互动、通知系统（基建+自动化触发）、账户安全（密码重置、登录锁定）、邮件/Webhook 占位。

## 你可写的文件（新建模块）
- `backend/notifications.py` —— 通知基建（`notify()` + SMTP 邮件）
- `backend/account_security.py` —— 密码重置、登录失败锁定
- `backend/social.py` —— 交流圈附件/@提醒（可选拆分自 main 内联）
- 其他你新建的 `backend/*.py`

## 禁止触碰
- `main.py` `db.py` `auth.py` `schemas.py`（路由与触发由 P1 装配/调用）

## 你要做的事（对照 `TEAM_PLAN.md` §5）
1. **通知基建（P0 核心）**：新建 `notifications.py`，导出 `notify(user_id, ntype, content, ref_id=None, company_id=1)`（写 `notifications` 表），并提供语义封装：`notify_register_pending(admin_ids)`、`notify_quiz_submitted(master_id, apprentice_name)`、`notify_anomaly(...)`。当前 `main.py` 内联的 `_notify` 由 P1 改为调用你的 `notify()`。
2. **通知自动化触发（P0）**：逻辑（调 `notify`）写好，但"在注册/检测处调用"由 P1 在 `main.py`/`auth.py` 接线。你需与 P1 对齐调用点。
3. **站内通知**：`/api/notifications` 与 `/read` 已存在，确保 `notify` 写入后能被正确读取、红点计数正确。
4. **P0 密码重置**：`account_security.request_password_reset(identifier)` 生成 `password_resets` 令牌（带过期）、`reset_password(token, new_pwd)` 校验并失效。提供这两个函数，P1 在 `main.py` 挂 `POST /api/password/reset-request`、`POST /api/password/reset`，并在 `schemas.py` 加模型。
5. **P1 登录失败锁定**：`account_security.check_lock(username)` / `record_attempt(username)` 实现 N 次/10 分钟锁定；P1 在 `auth.login` 调用。
6. **P1 SMTP 邮件**：`notify()` 内实现真实 SMTP 发送（用注册邮箱/手机号对应邮箱，先占位也可，但接口要通）。
7. **P2 办公软件 Webhook**：预留 `notify_via_webhook(platform, account, content)` 占位接口（企微/钉钉/飞书），不阻塞主流程。
8. **P2 交流圈附件 / @提醒**：`post_attachments` 表已有，补上传 API 与 @提醒→通知逻辑（抽到 `social.py`）。

## 验收标准

- [ ] 密码重置全流程可用（P0）

- [ ] SMTP 邮件发送打通（P1）
- [ ] Webhook 占位接口存在（P2）
- [ ] 附件上传 / @提醒可用（P2，时间允许）
