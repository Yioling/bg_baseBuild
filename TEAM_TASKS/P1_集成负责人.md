# 任务卡 · P1 集成负责人 / 契约 Owner

## 你的角色
团队唯一可以修改**枢纽文件**的人。你不写业务功能，你负责：冻结契约、维护数据库与鉴权、装配所有人的路由、最终合并与端到端测试。

## 你可写的文件
- `backend/db.py`（schema 单一真相源，32 张表）
- `backend/auth.py`（注册/登录/登出/token/角色守卫）
- `backend/main.py`（**所有** `@app` 路由的装配点）
- `backend/schemas.py`（Pydantic 请求模型）
- `backend/config.py`、`run.py`、`run_exe.py`
- `tests/`（冒烟测试）

## 禁止触碰
- 无（你是枢纽 owner）。但**不要**在 `main.py` 里写大段业务逻辑——业务应来自各模块导出的函数。

## 你的核心职责
1. **维护契约**：`API_CONTRACT.md` 的变更审批；任何人要加端点/字段，先找你登记。
2. **数据库**：原则上不改动 32 张表；确需加字段/表，由你统一在 `db.py` 落地，并通知全员。
3. **路由装配**：收到 P2~P7 的"函数位置 + 路径 + 守卫"后，在 `main.py` 写薄路由装配（参考现有模式：`api_xxx` 调 `Depends(auth_user)` + 角色守卫 + 调模块函数）。
4. **触发通知（P0）**：在 `auth.register` 或注册通过处、以及 `api_submit_quiz`（或 quiz 模块）处，调用 P7 提供的 `notify(...)` 实现"注册待审→管理员""提交检测→师傅"自动化。
5. **密码重置路由（P0）**：为 P7 的 `account_security.request_password_reset/reset_password` 在 `main.py` 挂 `POST /api/password/reset-request`、`POST /api/password/reset`，并在 `schemas.py` 加对应请求模型。
6. **Git 主分支保护 + 合并**：每日审核合并各 feature 分支；保证 `python run.py` 可起。
7. **端到端冒烟 + tests/**：建立最小 pytest，覆盖跨模块调用与 `company_id` 隔离。

## 关键现有函数（你拥有，别人依赖）
- `auth`: `register, login, logout, get_user, require_master, require_apprentice, require_admin, hash_password`
- `main`: `auth_user(request)` 依赖、`get_store()`、`_notify(conn,...)`
- `schemas`: `LoginReq, RegisterReq, CreateApprenticeReq, IngestPathReq, IngestUrlReq, PlanGenerateReq, AssessmentAnswerReq, ChatReq, CompanyPostReq, AssignMasterReq`

## 验收标准
- [ ] 所有人的模块函数都能在 `main.py` 无冲突装配，55 个原有路由不受影响
- [ ] 注册待审 / 提交检测 自动产生对应通知（P0）
- [ ] 密码重置接口可用（P0）
- [ ] `tests/` 有可运行的冒烟用例，主流程端到端跑通
- [ ] `python run.py` 启动无报错，`http://localhost:8000` 正常
