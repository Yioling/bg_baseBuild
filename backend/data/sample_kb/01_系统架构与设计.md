# 智能订单交易系统 · 系统架构与设计

## 1. 系统概述

智能订单交易系统是一套面向电商场景的高并发订单处理平台，核心职责是承接用户下单、支付、履约全链路交易。系统日均订单量百万级，大促峰值 QPS 可达十万级。设计目标是在保证交易正确性的前提下，兼顾高可用、高扩展与强一致性。

## 2. 整体架构分层

系统采用经典的分层架构，自上而下分为：

- **接入层**：API 网关，负责鉴权、限流、路由、协议转换。所有外部请求统一由网关收口，便于做全局限流和熔断。
- **应用层**：按业务域拆分为订单服务、支付服务、库存服务、营销服务、风控服务等多个微服务，每个服务独立部署、独立扩缩容。
- **领域层**：封装核心业务逻辑，如订单状态机、库存扣减策略、优惠计算引擎。领域层不依赖任何外部中间件，可独立单元测试。
- **基础设施层**：MySQL 持久化、Redis 缓存、RocketMQ 消息队列、Elasticsearch 搜索。

## 3. 微服务拆分原则

微服务拆分遵循"高内聚、低耦合"原则，按业务能力边界划分：

1. **订单服务**：负责订单创建、状态流转、订单查询。是整个交易的核心枢纽。
2. **支付服务**：对接第三方支付渠道（微信、支付宝、银联），处理支付回调与对账。
3. **库存服务**：负责商品库存的扣减、回滚、预占。
4. **营销服务**：负责优惠券、满减、积分等促销计算。
5. **风控服务**：负责交易反欺诈、限购、黑名单校验。

服务间通信以异步消息为主（解耦、削峰），同步调用仅在强依赖场景使用（如下单时库存校验）。

## 4. 技术选型

| 领域 | 选型 | 选型理由 |
|------|------|----------|
| 开发框架 | Spring Cloud Alibaba | 国产生态完善，Nacos 注册中心 + Sentinel 限流 |
| 数据库 | MySQL 8.0 | 支持 InnoDB 行锁，满足交易强一致需求 |
| 缓存 | Redis 6.x Cluster | 高性能缓存 + 分布式锁 |
| 消息队列 | RocketMQ | 支持事务消息，适合订单分布式事务场景 |
| 搜索 | Elasticsearch | 商品与订单全文检索 |
| 注册中心 | Nacos | 服务发现 + 动态配置 |

## 5. 高可用设计

系统从三个层面保障高可用：

1. **服务无状态化**：应用服务不保存会话状态，所有状态下沉到 Redis/MySQL，任一实例宕机可被负载均衡剔除，流量自动转移。
2. **多机房部署**：核心服务双机房部署，数据库主从同步，机房级故障可切换。
3. **熔断降级**：通过 Sentinel 配置接口级熔断规则，当依赖服务（如第三方支付）超时率升高时自动降级，避免级联雪崩。

## 6. 容量与性能目标

- 单机 QPS：5000
- 集群 QPS：10 万（大促）
- 接口 P99 延迟：下单接口 < 200ms，查询接口 < 50ms
- 可用性 SLA：99.95%

架构设计是交易系统的骨架。分层清晰、服务边界合理、技术选型匹配业务特征，是支撑后续业务快速迭代与平稳运行的基础。下一章将深入订单核心业务流程。
